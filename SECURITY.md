# Security and data protection

## Reporting a vulnerability

Please report security problems privately through GitHub: **Security →
Report a vulnerability** on this repository. Do not open a public issue.

## What is protected

The system collects interview answers from research participants. These may
contain personal information, so the main goals are:

- only the participant can see or change their own session;
- only the researcher can create links or export data;
- audio is never stored;
- a participant can withdraw at any time and have their data deleted.

## Controls

| Area | How it is handled |
|---|---|
| Secrets | All secrets come from environment variables, generated by `scripts/generate_env.py` with a CSPRNG into `.env` (mode 0600, git-ignored, docker-ignored). The researcher token must be ≥ 32 characters, and placeholder-looking values are refused at startup. Google credentials are a compose secret, readable only by the gateway's container user. |
| Researcher routes | Every `/api/researcher/*` route requires the bearer token (constant-time comparison) and has its own rate limit. |
| Participant authentication | Each participant link carries a 256-bit random token. It sits in the URL fragment, which browsers never send to servers or put in `Referer` headers. The web app moves it to `sessionStorage` and removes it from the address bar. Only its SHA-256 hash is stored, so a database leak does not reveal working links. |
| Users access only their own data | Every participant request is bound to the session that the token resolves to. The API takes no participant IDs that could be swapped. Answers must match the question currently being asked. |
| Input validation | Pydantic models with `extra="forbid"`, length limits on every field, an audio size and duration cap, a content-type allow-list for audio, and a request-body size limit in both the gateway and Caddy. |
| XSS | The web app never uses `innerHTML` (a test enforces this). All text is set with `textContent`. CSP is `script-src 'self'` with no inline scripts; the API's CSP is `default-src 'none'`. |
| CSV injection | Exported cells that start with `= + - @` (or tab/CR) are prefixed with `'`. |
| Rate limiting | Answer submission is limited per participant. Researcher routes are limited per client address, taken from the `X-Forwarded-For` header that only Caddy can set (the gateway port is not published). |
| CORS | No CORS headers are sent. The app and API share one origin, so other sites cannot call the API from a browser. |
| Security headers | CSP, HSTS (gateway and Caddy), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy`, a `Permissions-Policy` that allows only the microphone (same origin), and `Cache-Control: no-store` on the API. The `Server` header is removed. |
| Debug off | FastAPI `debug=False`, and the interactive docs and OpenAPI schema are disabled. Unhandled errors return a generic message; details are logged only. Rasa runs without `--enable-api` and without `--cors`, so its model-management API does not exist. |
| Exposed files | Only `gateway/static` is served. CI checks that `/.env`, `/.git/config`, `/docs` and `/openapi.json` return 404. `.dockerignore` keeps `.env`, `secrets/`, `.git` and local models out of images. |
| Database | PostgreSQL is reachable only on an internal network. The app uses its own non-superuser role that owns only its database (`deploy/postgres-init`), with SCRAM-SHA-256 authentication. Migrations are versioned with Alembic. |
| Passwords | The system has no user passwords. Participant links and the researcher token are random secrets; links are stored only as hashes. |
| Network isolation | Only Caddy publishes ports. Rasa and the action server sit on internal networks with no internet access, and the action server is reachable only from Rasa. Only with voice answers enabled does the gateway get an outbound route, which it needs for Google. |
| Containers | Non-root users with fixed UIDs, read-only root filesystems, `cap_drop: ALL`, `no-new-privileges`, and `pip` removed from runtime images. |
| Dependencies | Every requirements file is hash-locked (`pip install --require-hashes`). CI runs pip-audit, bandit and ruff on every push; Dependabot proposes updates weekly. |
| Secrets in git history | gitleaks scans the full history on every push. |

## Data protection (GDPR-style)

- **Consent** is recorded with a timestamp before any question is asked. Participants must confirm they are adults.
- **Data minimisation.** Participants are known only by a pseudonym such as `P007`. No names, e-mail addresses or IP addresses are stored. Gateway logs contain the request ID, method, path, status and duration. They contain no answers and no IP addresses. Caddy's access log records client IP addresses for abuse monitoring. Container logs are rotated (3 × 10 MB per service), so old entries are overwritten.
- **Audio** goes straight to Google Speech-to-Text and is discarded after transcription. It is never written to disk or to the database.
- **Withdrawal.** The participant's Withdraw button deletes all their answers immediately, and the link stops working. The researcher can also delete a participant entirely (`DELETE /api/researcher/participants/{pseudonym}`).
- **Export** excludes withdrawn participants.
- **Retention.** Delete the database volume (`docker compose down -v`) once the analysis is complete and the retention period in your ethics approval has passed. Exported CSV files are git-ignored. Store them only in approved locations.
- If you enable speech recognition, add Google Cloud to your privacy notice as a processor. Choose a data region that matches your ethics approval.

## Rasa Open Source: reviewed dependency advisories

Rasa Open Source 3.6.21 is the final open-source Rasa release. It requires
Python ≤ 3.10 and pins many dependencies to old versions. This project:

1. **Upgrades every pinned package that can be upgraded safely**: aiohttp, cryptography, protobuf, pydantic, pymongo, dnspython, sentry-sdk and setuptools (`rasa/overrides.txt`). The upgraded set is validated, trained and tested in CI, and the end-to-end test checks that Rasa answers every turn.
2. **Runs Python 3.10 from Ubuntu 22.04 LTS**, which still receives security updates. Upstream Python 3.10 has reached end of life.
3. **Isolates Rasa and the action server.** They have no published ports, no internet access, run as non-root on read-only filesystems, and have no model-management API. Their only client is the gateway, which sends validated text of bounded length.

The advisories that remain are listed with reasons in
`rasa/audit-exceptions.txt`, and CI fails on any advisory not on that list. In short:

| Package | Why it cannot be upgraded | Why it is not reachable here |
|---|---|---|
| sanic 21.12, sanic-cors | Rasa and rasa-sdk require sanic 21.12; sanic-cors has no fix | Services are internal only; clients send fixed-length JSON; CORS is off |
| tensorflow 2.12.0, keras 2.12 | Rasa pins TF 2.12; 2.12.1 would force a vulnerable cryptography | Issues need crafted tensors or model files; only the image's own model is loaded |
| skops 0.9, scikit-learn 1.1 | Pinned by Rasa | Unsafe model loading and TF-IDF leakage; neither is used |
| pillow 12.3, filelock 4.1, dnspython 2.8 | Fixed versions need Python ≥ 3.11 | No image handling, no shared lock directories, no MongoDB |
| protobuf 4.25.8 | TF 2.12 needs protobuf < 5 | No untrusted protobuf parsing |
| setuptools 81, wheel 0.45 | Rasa needs `pkg_resources` and `packaging<21` | Build-time and Windows-only issues |

If you need to remove this residual risk entirely, set
`INTERVIEW_ENGINE=scripted` and leave the `rasa` and `actions` services out.
The interview is identical; only the small talk is interpreted by keywords
instead of NLU. The long-term fix is migrating to a maintained dialogue
framework.
